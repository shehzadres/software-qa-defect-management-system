# Recruiter Guide

## 60-second project walkthrough
1. Open the [QA dashboard](../reports/qa-dashboard.html) for the recorded execution snapshot.
2. Review the [test plan](TEST_PLAN.md) and [test case catalogue](../test-cases/test-cases.csv) to see scope and test design.
3. Open the [live execution matrix](../test-cases/live-execution-results.csv) and [JSON evidence](../reports/live_execution_evidence.json) to inspect outcomes.
4. Review [requirements traceability](../requirements/requirements.csv), [SQL queries](../sql/reports.sql), and [defect lifecycle](DEFECT_LIFECYCLE.md).
5. Inspect the [TaskFlow browser screenshot](../reports/taskflow_dashboard_after_login.png).

## Skills demonstrated
Requirements analysis, risk-based test planning, manual test design, negative and boundary testing, authorization testing, exploratory testing, defect documentation, Jira workflow familiarity, SQL data validation, Playwright browser automation, and evidence-based reporting.

## Accurate talking points
- I designed 32 test cases across 10 documented requirements.
- The saved local run passed all 32 mapped cases.
- The runner combines Playwright browser interaction with API and database assertions.
- I maintained a separate set of simulated defects for practicing severity, priority, triage, and Jira workflows.
- This is a controlled portfolio demo, not a production security certification.

Avoid claiming that all tests are browser UI automation or that seeded defects were found in the live run.
